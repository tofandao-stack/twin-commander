# File operation progress

Native copy, permanent delete, trash and move requests open a nonmodal progress dialog with **Current file** and **Overall progress** bars. Copy/delete invoked by drag-and-drop uses the same dialog. The background queue also shows both bars for the selected job, or initially the running job.

Copy reports bytes written for the current file independently of bytes written across the operation. The current bar resets for each file; empty files and symbolic links complete as individual entries. Overall copy progress uses byte totals where there are file bytes, and entry totals for zero-byte trees. Recursive permanent deletion uses entry counts, including directories. A file's delete is an atomic filesystem call, so its own bar advances from pending to complete rather than simulating a byte transfer. Trash and same-device moves report selected-entry completion; desktop trash internals are managed by the filesystem/desktop API.

A cancellable worker-side scan collects advisory totals before recursive copy/delete. It does not follow symbolic links or descend across filesystem boundaries, and is bounded to one million entries and 256 levels. During counting, or when a reliable total cannot be collected, the overall bar is indeterminate. A failed scan does not bypass the existing mutation checks or prevent per-entry operation errors from being reported. Files can change after counting, so totals are estimates; existing source identity, staging and no-overwrite checks remain authoritative.

Pause/Resume and Cancel use the existing job controls. Background or closing the progress window leaves the job in the queue. Successful jobs close their transfer window automatically; failed/cancelled windows remain available to close. Failed and cancelled jobs retain partial progress instead of being forced to 100%. Completed job status represents the whole request, including any skipped conflicts, rather than a claim that every planned byte was copied. Earlier committed files remain applied on cancellation, as before.

The two bars share a thread-safe snapshot containing the native current path, per-file bytes, overall bytes, entry counts and scan phase. UI polling occurs at 100 ms in the transfer dialog and 200 ms in the queue. The original aggregate counters and report/journal formats are retained. Other queued tools continue to use their existing reporting and may show indeterminate progress while running.

All nine CTest suites pass in Debug (87.29 s) and ASan/UBSan (66.52 s, leak reporting disabled). New tests check independent file/overall values and resets, recursive delete counts and symlink safety, zero-byte files, partial/cancelled/failed progress, and the automatic dialog lifecycle for a real drag-and-drop copy. An offscreen rendered dialog was inspected with 60% current-file progress and 30% overall progress. Workspace-prefix installation and installed version/help checks pass; `git diff --check` passes. The optional large-directory measurement was skipped.
