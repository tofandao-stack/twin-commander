# Direct file-operation progress

Copy, trash and permanent-delete commands now go straight from the selected entries to the running progress dialog. This applies to F5, F8/Delete, Shift+Delete, menu/context commands and native copy/delete drops. Copy uses the opposite panel as destination and the existing no-overwrite default. There is no preparatory destination/confirmation or count window for these actions, including when older confirmation/count preferences are enabled. Counting takes place inside the operation worker and is shown by the progress window. Move, rename, new-folder and new-file inputs retain their existing workflows.

## Transfer window

The compact foreground window has a centered operation/current-file-rate line, **From:** and **To:** paths, two progress bars with percentages on their right, file/entry and byte counters, elapsed time and estimated remaining time. Total transfer rate appears in the overall bar when measurable. Long paths are elided for display; hover exposes the complete path. Click either counter to switch between completed/total and remaining amounts, with remaining values prefixed by a minus sign.

Controls appear in **Pause, Cancel, Background** order. Foreground operation is modal to its parent window. Background keeps the progress window available, unlocks the main window, and changes the button to Foreground so the same operation can be brought back. Background completion does not deliberately activate the main window or move keyboard focus. Cancel, Escape and the window close button cancel pending work; they no longer silently leave a foreground job running. Successful transfers close their progress window. Failed/cancelled job details remain available through existing reports and the queue.

The copy background view exposes a **Speed limit** checkbox and numeric kB/s field. Its limit applies to native buffered, Qt-buffered and kernel-assisted copy paths. Changes, disabling, pause and cancellation are observed during throttling. The last numeric value is stored; new operations start without a cap. Rate estimates exclude observed paused/scanning intervals and need enough samples before they appear. Elapsed/remaining time and rates are observational estimates, not a guarantee of disk throughput or completion time. The queue displays the same two progress bars for its selected operation.

Copy progress counts bytes written. Deletion advances per completed entry; an individual filesystem deletion is atomic, so the file bar advances from pending to complete. Empty files and symlinks complete without a divide-by-zero calculation. Recursive counting is advisory, cancellable, bounded to one million entries/256 levels, and does not follow symlinks or descend across filesystem boundaries. Unknown totals use an indeterminate overall bar. Failed/cancelled jobs keep partial progress. Earlier committed files remain applied on cancellation; staged copy output still uses the existing no-overwrite/identity checks. Skipped conflicts are part of a completed request, not a claim that all planned bytes were copied. Other queued tools retain their existing backend contracts.

## Reference evidence and limits

The repository targets Total Commander 11.58.1 x64, built-in English. The local official reference executable supplies the `From:`, `To:`, `Copy:`, `Deleting:`, Cancel and Background strings. Its bundled `proc_copy.htm` documents counters that toggle to remaining amounts, full-path tooltips, and background/foreground transitions. Its `whats_new.htm` describes total speed in the second progress bar. The Win32 `DOWNDLG` and `DOWNDLGLIST2` resources describe background/queue variants, not a certified foreground runtime layout, so their dimensions are not misrepresented as a foreground pixel reference.

Reference inputs originate from the [official 11.58.1 installer](https://totalcommander.ch/115801/tcmd115801x64.exe); hashes are retained in [reference-manifest.json](reference-manifest.json). Official discussion also identifies [Pause, Cancel and Background in the running copy window](https://ghisler.ch/board/viewtopic.php?t=41733). Runtime examples informed the compact arrangement, but no controlled Windows 11.58.1 runtime capture exists in this workspace.

This implements the native direct-start workflow and the described transfer-window controls. Pixel-for-pixel Windows rendering and complete Total Commander behavioral equivalence are **not certified**: Qt fonts/window decoration, Linux trash behavior, conflict handling, recursive directory replacement/merging, and non-native provider/archive contracts retain their documented native limits. Runtime file errors can still produce result dialogs. Skipping the startup prompts is the requested workflow change, rather than a statement about Total Commander's default F5 confirmation behavior.

## Validation

All nine CTest suites pass against the final source in Debug (95.40 s) and ASan/UBSan (83.61 s; leak reporting disabled). Tests cover immediate copy/delete with old startup flags enabled, F5 selection/focus and cancellation, per-file/overall independence, remaining-counter toggles, published destinations, measured rate/time fields, foreground/background modality, pause/resume, speed-cap wiring and real throttled copies, interruptible limiter waits, and failure releasing foreground modality. The rendered compact window was visually inspected. Workspace-prefix installation and installed version/help checks pass; `git diff --check` passes. The optional large-directory measurement was skipped.
